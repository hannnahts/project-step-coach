# 演示：待办列表的筛选与分页

> 这是一个虚构的示例，用来展示 skill 的回答结构；它不代表真实项目记录或用户反馈。

## 用户提供的项目上下文

```text
我刚完成待办列表的筛选和分页：筛选条件变化后会回到第一页，查询会带上当前筛选条件和页码，没有匹配项时会显示空状态。请复盘这个环节。
```

## Project Step Coach 的示例回答

### 1. 本环节完成

你完成了待办列表的筛选与分页：用户可以缩小结果范围，逐页浏览匹配项；切换筛选条件后回到第一页，没有匹配项时能看到空状态。

### 2. 原理与术语

筛选会改变结果集合。假设用户正在第 5 页，换了一个只剩 2 页结果的筛选条件，如果还停留在第 5 页，页面就可能看起来像“没有数据”。重置到第一页后，再用新筛选条件和当前页码查询，可以让页码与新的结果集合对齐。

- **筛选条件（filter）**：决定哪些待办事项符合本次查询。
- **分页（pagination）**：把较长的结果集合拆成多页，减少一次展示或加载的数量。
- **空状态（empty state）**：没有结果时给用户的界面反馈。最好让用户知道是筛选条件没有匹配项，并给出清除或调整筛选的路径。

### 3. 产品级思考

这个行为能减少“筛选后怎么什么都没了”的困惑。除了呈现空状态，还可以确认两种情况是否容易分辨：任务确实为空，以及请求失败导致暂时拿不到结果。用户修改筛选后是否能理解当前条件、并轻松恢复到完整列表，也值得观察。

可以用这些信号检查体验：筛选后用户能否找到目标事项、是否频繁清空筛选，以及空结果时是否容易继续操作。下一步可以确认清空筛选的入口和请求失败时的反馈是否清楚。

### 4. 模拟面试：三题

1. **概念题：** 为什么筛选条件变化后，通常要重新从第一页开始，而不是保留原页码？
2. **设计取舍题：** 如果待办数据持续增长，你会如何判断筛选和分页应放在客户端还是服务端处理？
3. **实际场景题：** 用户换了筛选条件后看到空列表，你会怎样区分“确实没有匹配项”和“查询失败”，并定位问题？
